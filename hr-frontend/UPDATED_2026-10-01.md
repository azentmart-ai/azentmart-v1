# AzentMart HR Platform — 2026-10-01 Update

This update integrates the requested enterprise HR workflow changes into the existing project without rebuilding the application from scratch.

## Included changes

### Global UX
- Shared AzentMart People Operations footer for the authenticated workspace and Home page.
- Global humanized AI HR Assistant with an original headset-wearing avatar.
- Public Home chatbot mode for product questions.
- Authenticated chatbot mode for grounded HR workspace questions.
- Central search remains connected to backend records.

### Employee onboarding
- Reworked `/onboarding/new` into a true six-step flow.
- Next/Previous navigation stays inside the onboarding form.
- Step validation prevents moving forward with incomplete required data.
- Review step allows returning to a specific section.
- Employee creation is connected to the existing employee API.
- Onboarding journey is created and persisted in PostgreSQL.
- Uploaded onboarding documents are attached to the created employee.
- Onboarding details are persisted with the onboarding record.
- Final submission opens the created onboarding journey instead of redirecting to Home.
- Added onboarding task flow: offer, employee record, documents, verification, IT, orientation, manager introduction, training and final review.
- Added AI onboarding analysis endpoint and UI integration.

### Payroll
- Payroll list now returns employee-linked details from PostgreSQL.
- Added payroll summary endpoint.
- Added approve, approve-and-lock and lock actions.
- Added payslip PDF generation.
- Added Bank NEFT CSV generation.
- Added all-payslips ZIP generation.
- Added payroll CSV export.
- Added employee bank fields (bank name, account number, IFSC).
- Added professional tax and other deductions to payroll records.
- Added `/api/ai/payroll/chat` for grounded payroll AI responses.
- Removed frontend demo payroll fallback records.

### AI / RAG / MCP
- Global AI agent now retrieves authorized database context before answering.
- Payroll, onboarding, employee, attendance, leave and ticket context are supported.
- Existing RAG retrieval is included as approved knowledge context.
- Existing MCP registry remains available for approved tools.
- OpenAI integration is optional through environment variables; without a key, the assistant returns grounded system information instead of fabricated answers.

### Backend / database
- Added non-breaking schema columns through startup migration checks.
- Added onboarding JSON details storage.
- Added employee banking fields.
- Added payroll deduction fields.
- Added `google-genai` to backend requirements because the existing support module imports it.

## Environment

Use the existing `.env.example` files. Never commit real secrets.

Frontend:

```env
VITE_API_URL=/api
VITE_DEV_API_PROXY_TARGET=http://localhost:8000
```

Backend should be configured with PostgreSQL, JWT secret, CORS origin, upload directory and optional OpenAI settings.

Optional AI settings:

```env
OPENAI_API_KEY=
OPENAI_MODEL=gpt-4o-mini
ENABLE_PGVECTOR=false
```

## Run

### Backend

```powershell
cd backend
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

### Frontend

```powershell
cd frontend
npm ci
npm run dev
```

The packaged project intentionally does not include `node_modules`, `.venv`, compiled Python caches or the real backend `.env` file.
